# Conversation loading

The workspace's native harness transcript remains authoritative. iOS keeps an in-memory cache of recent conversations; it does not persist another transcript database.

- All chat lists use the latest native activity date and compact relative times.
- Opening the same chat shares one model and one initial history request. Navigating back lets that request finish, and the list shows its loading state for both initial loads and cached refreshes. Rapidly opening and closing the same chat joins the pending request without scheduling another tail read.
- Saved history loads alongside native terminal-owner discovery. Slow or failed discovery cannot hide the transcript; Send, voice, compaction and forking wait for ownership verification. A failed check keeps saved messages readable and offers Retry without starting another agent process. Opening a healthy service uses cached release metadata and configures optional notifications in the background.
- Unsent composer text belongs to a shared per-chat draft, separate from the transcript cache. Typing updates only that draft in memory. Leaving the screen or backgrounding persists its changed text as one local string, so returning or relaunching restores it without a network request. Successful submission clears only the submitted revision; newer typing survives a delayed acknowledgement. Chat deletion removes its draft.
- Reopening displays the cached tail and live reply immediately, then checks the current run. If the same run is still active, its committed history prefix stays cached and the stream requests only events after the last applied sequence. A cold/evicted running chat reads its newest history page and active run snapshot concurrently, then publishes the prompt and partial response together. The stream resumes from that same snapshot's cursor without downloading it again. Concurrent openers share one restore and subscription. Conversation history and live output remain in memory; only unsent drafts are persisted locally.
- Acknowledged new-turn messages enter the shared model before any history reconciliation. Lagging native pages retain that prompt and its attachments until its native identity appears, without matching an earlier identical prompt. Cached live user/assistant parts also keep the transcript visible while history refreshes, even when no committed messages have arrived yet. Queued follow-ups continue to appear at their native consumption boundary.
- If the run finished or changed, or work continued in a computer's native CLI, a conditional newest-page read checks the cached revision. An unchanged response keeps the transcript and already loaded older pages without parsing or transferring history again. A changed response contains the bounded newest page and its own older-page cursor. Intermediate messages are fetched only when scrolling up; the native conversation is unchanged. A read that finished while hidden can serve an immediate return. If the user is reading older messages and the fetched tail has no overlap, their current window stays visible until Jump to latest or a new visit adopts the fetched page. This retains the reading position without joining disconnected history ranges.
- Visible chats keep a live subscription through brief inactive states such as Notification Center or system gestures. Only navigating away or actually entering the background detaches the viewer. Neither sends Stop to the daemon. Returning resumes the cached cursor once; temporary overlays preserve live output, disclosure state, the draft, and the existing table.
- The cache retains at most six inactive conversations within a conservative 32 MiB payload allowance. Visible conversations and in-flight operations are protected. Memory warnings discard inactive entries; deletion invalidates cached content.

The initial loading indicator uses the conversation's bundled harness logo inside an indeterminate ring. Project cards reuse that same component on the right for running agents, preserving the brand artwork. It honors Reduce Motion and pauses for background or cached disconnected activity; only the ring redraws during animation. Cached catch-up keeps the transcript and composer visible and uses a small indicator in the navigation title. A 250 ms delay prevents quick freshness checks from flashing a spinner. Older-page loading uses an indicator inside the transcript's scrolling header, independent of title refresh. Its reserved paging space avoids changing row heights when the indicator starts. A completed reply and its native history page replace the cache together. Positioning goes directly to the latest row instead of animating through hundreds of intermediate rows.

Older paging remains available while latest history, a restored run or the connection is refreshing. The cached model owns page requests, so losing a particular SwiftUI view never restarts a pending page. Identical in-flight cursors share a request, including completion reconciliation, while latest-page requests distinguish run-state transitions so a pre-Stop snapshot cannot stand in for the final history. Older results merge only into the head/cursor they were requested for; a newer visit or appended reply does not invalidate them, but jumping across a history gap does. A deferred newest page counts toward the existing cache byte limit.

The saved event cursor always belongs to the published live state. A replay suffix is folded separately until `ready`; navigating away discards only that unfinished suffix and resumes the previous checkpoint next time. A transport reconnect during replay retains its buffer. Sequence gaps recover a fresh daemon snapshot rather than retrying a permanently missing suffix. Legacy streams still replay atomically without cursor support. This uses the existing daemon protocol and adds no background mobile subscriptions or daemon history cache.

Tapping the transcript, loading state, or empty conversation dismisses the composer keyboard while preserving the draft. A native tap recognizer resigns editable input in the conversation's own window, even when SwiftUI's focus state does not reflect the keyboard inside a safe-area bar. It leaves read-only message selection alone and allows tool controls, links, and interactive scrolling to keep receiving their gestures; dismissing focus does not recreate the table or reload history. The composer and presented sheets are outside its touch area.

Rendered text blocks use native word selection: double-tap a word, adjust the handles, and copy the selected rendered text. MarkdownUI retains the block layout, lists, tables and image rendering; native text preserves emphasis, links, inline code and the shared code highlighting. User bubbles keep their literal text. While selecting, that message's layout stays fixed while incoming tokens continue accumulating; ending selection displays the latest text. Long-press → Select text opens the pressed part's original raw Markdown separately, and user messages retain Edit and resend in their native text menu.

History requests use `paged=true`, `limit=12`, and `maxBytes=1048576`. The service returns complete messages with `hasMore` and `before`; scrolling upward requests the preceding page. Older services can return their original array, decoded without a second request. The transcript uses reusable table cells for individual parts and expanded command children.

Latest pages can include an opaque `revision`. The app retains it across visits and completion and sends it as `ifRevision`, without a `before` cursor. `{ "notModified": true, "revision": "…", "messages": [], "hasMore": false }` is a validation response, not an empty transcript: it never clears cached rows or pagination. The daemon checks per-chat mutation counters and native file stats (including Codex ancestors). Native CLI changes, run transitions and question answers invalidate the token; other chats and ordinary settings do not. A restart changes the daemon epoch. No worker watches or reserializes idle transcripts. Older daemons ignore the query and return a normal page. Concurrent app openers share the same status/history request.

At the completion of a continuously watched turn, the client reads back through that turn's start before dropping the live snapshot. This preserves Claude turns that span several native messages. Reopening a completed run and completing a restored run use the authoritative newest page instead, keeping earlier tools and queued inputs in their native pages. A run that finishes during catch-up gets one final tail read after its terminal status. Existing reader pagination still preserves overlapping pages and handles invalidated native cursors.

The new service advertises `historyPageVersion: 1`. Its byte budget is soft: up to two newest messages remain whole even when larger than the budget (one when `limit=1`). This keeps a large reply beside its adjacent input and never truncates tool output or diffs. Native parsing is cached with file identity, size, and modification-time validation, shared reads, bounded memory, and independent copies for mutable protocol fields. These service optimizations require a daemon release; the smaller requests, navigation cache, and presentation changes also work with older services.

The attachment menu offers Photo Library, Take Photo and Choose Files. It uses the shared native menu component so custom icons preserve their action labels and accessibility. Sent photos and file cards appear above the text bubble. Photos open in the image viewer; documents open in a native file preview with a fixed Done button.

Command output stays compact in the transcript: at most 12 preview lines and 4,000 characters. Full output reuses the read-only file editor, including its viewport-based text rendering, native selection, and horizontal scrolling. Done and Copy remain in the sheet's toolbar. Tool headers, footer collapse buttons, and context-menu actions stay independent controls; the disclosure header's accessibility identifier does not override its children.

Agent errors start collapsed with a single aligned title and icon. Expanding shows at most six lines; **View full error** opens all diagnostic text in a selectable, scrollable native sheet with Copy and Done. Rejected sends and failed question replies use the same component, retain the user's draft, and can be dismissed. A completed error already present in the transcript is not duplicated above the composer or shown in an automatic alert.

The composer accepts up to eight attachments, 16 MiB per file and 48 MiB total. Photos are normalized, stripped of source metadata and compressed to at most 4 MiB off the main thread. With `attachmentUploadVersion: 1`, uploads use resumable 384 KiB chunks over the existing authenticated connection, report progress and send durable references in `options.attachments`. Older services retain their bounded inline image path; documents require a service update. Failed sends restore attachments, and request receipts are reused only when both text and attachments match.

`imageAttachmentsVersion: 1` advertises image-only turns and durable user-message attachments.
Claude's native image blocks and Codex's image/local-image records map to the same `attachments`
field. Codex's image wrapper tags and repeated native input records collapse into one user bubble.
Recorded bytes preserve a preview if a native transcript references a deleted temporary image.
The UI keeps thumbnail sizes fixed while decoding and reuses the file viewer for zooming.
The daemon preserves attachment references when reloading, forking or transferring native conversations.
