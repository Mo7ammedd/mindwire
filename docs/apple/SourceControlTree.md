# Source Control tree

The layout control beside **Files / Review** switches between **List** and **Tree**. List remains the initial layout; the choice is saved separately from the file explorer's layout. Tree also works with inline Review previews. Its menu can expand or collapse all folders.

Both screens render through the same `FileTree` and `FileTreeListStyle`, extracted from the explorer. This includes folder disclosure and child rendering, arrow-only folders, single-line names, 18-point file icons, 16-point text, and the explorer's saved density setting. Source Control supplies diff counts as the trailing accessory. It no longer renders the larger two-line Git cards in Tree mode. List mode retains those existing cards.

**Customize Tree** is available from either screen's ⋯ menu, the Source Control layout menu, and Files' View Options. One shared sheet provides a live preview, horizontal spacing (8–28 points), vertical row padding (2–14 points), Compact folders, and Reset to Defaults. Preferences persist locally and apply to both screens. Default indentation is 12 points with a 4-point icon/text gap; default row padding remains 7 points, scaled by the existing density setting.

**Compact folders is on by default.** Chains containing only one subfolder appear as one row, such as `apps › src › modules`. A file, multiple subfolders, or an empty directory ends the chain. The row opens the terminal folder's children; its context actions target that terminal folder. Paths and file actions remain unchanged. Folder selection expands the chain into individual rows so each real folder can still be selected. Compact groups retain a stable root identity and preserve expansion when the setting changes. Very long chains continue in another group after 32 components.

Both trees explicitly use zero spacing between rows. In Files mode, the Git action modifier wraps the shared row directly; only Review adds a stack for the inline diff.

`GitFileActions` supplies the same stage/unstage, discard, and copy-path actions to both layouts. Swipe-left actions use text only to fit the compact row; their native button backgrounds retain contrast in both themes. Context menus retain their icons. Inline progress replaces the file glyph, and opening a file uses the existing diff viewer. Review can still show an inline diff below the shared tree row. Rename origins are retained in the file's accessibility hint and diff details rather than adding another line to the tree.

`GitChangeTree` adapts the current Git status to the shared tree's snapshot source. It does not list directories or load diffs. Deleted files, untracked files, renames, and staged/working changes remain in the correct groups. A deleted file replaced by a directory gets distinct file and folder identities. Case-sensitive names retain deterministic ordering. The shared renderer flattens expanded snapshot branches into row descriptors, so every ForEach item is exactly one native List row. An explicit one-row container sits outside conditional loading/action modifiers; otherwise List still evaluates every row to discover its count. Both snapshot and workspace sources use the same `FileTreeNodeRow` for appearance and actions. Collapse, compact folders, and expansion retain their existing identities.

The explorer supplies the workspace source instead: opening a folder follows its single-subfolder chain, without scanning unopened sibling directories. Only workspace directories receive a loading task; files and prepared Git rows do not schedule empty tasks when they appear. Each path has one in-flight read and a revision-based cache for the lifetime of the open tree. Collapsing or changing preferences reuses loaded children. Refresh invalidates visible listings; late responses cannot overwrite newer results, and failed reads keep the last usable listing.

Each section retains its own expanded folders while refreshing or switching layouts. Searching builds a tree of the matching paths, including matches against rename origins, with temporary expansion state. Clearing search restores the previous folder expansion. The existing staged-section collapse control and bulk actions remain available.

In Tree mode, one permanent native `safeAreaBar` extends the navigation area. At the top it shows a compact branch selector and History. As the first visible row enters a change section, the same bar shows that section's actions and its repository-relative folder, such as `apps › api › modules`. Its scaled 44-point content height and four-point bottom padding stay fixed through these transitions. The navigation and context bar share the page background, protecting text from files scrolling behind them. The native edge effect remains below the bar. Repository totals and Files / Review share one compact overview section, without the former branch capsule or separate footer gaps.

The path gets a full-width row beneath the section title and actions. Long paths reveal the current folder automatically and scroll horizontally to earlier parents, without ellipses or wrapping. Separators use 35% opacity. Branch selection and History also remain available in the repository menu while viewing a folder. Inline section headings scroll normally with their files; a second pinned section header is no longer layered below the bar.

The native navigation bar stays in place, keeping the controls away from the modal's rounded corners. Reversing scroll direction changes neither navigation visibility nor the list's insets. The context bar is installed for the entire tree presentation, not inserted or removed in response to scrolling. There is no custom pinning overlay, pan-gesture hook, or show/hide animation. The horizontal breadcrumb resets only its own native scroll view when the folder changes; it never calls `scrollTo` on an ancestor. The interaction fixture presents Source Control inside a native sheet, matching the project flow.

The context follows the first visible file or folder below the native safe area in either scroll direction, including partly visible Review previews. Root files keep their section without an old folder path. Returning to the overview restores the branch row. Each section retains its own controls, including staged collapse and bulk actions, and displays a path only when the visible file belongs to that section.

`GitScrollBreadcrumb` is read-only: it observes the native List's offset and actual content-size changes to update the path text. Each offset callback checks the native top inset against a cached reading range; it no longer enumerates or converts pinned header frames. It coalesces updates and inspects only visible UIKit cells when that range or layout changes. Weak markers resolve their cell on attachment instead of repeating the ancestor walk and scheduling work on every layout. Only the context bar observes the selected folder. The helper never sets scroll offsets, changes insets, installs gestures, or adds directory requests or timers.

`GitFileTreeRows` caches its prepared structure by file paths and updates the change lookup separately when statuses or counts change. Surrounding view updates do not sort or reconstruct that tree. Viewport-height observations are active only for the empty state. A DEBUG-only fixture probe reads row/body/build counters and scroll position on demand. In that isolated fixture, a display link measures actual drag/deceleration frame intervals and stops when scrolling ends; normal app sessions never create it. The scroll check verifies bounded initial row creation, cold short drags in both directions, unchanged scroll insets, independent horizontal breadcrumb scrolling, unchanged tree body/build counts, and folder collapse/reopen after scrolling.

`GitChangeTreeTests` covers grouping, collapse, stable IDs, case-sensitive and numeric names, file/directory replacements, rename origins, and a 10,000-file status. `FileTreeBranchTests` covers compact boundaries, unknown/deep directories, shared reads, stale responses, and retry recovery. `GitScrollBreadcrumbTests` checks folder transitions, partial previews, section/overview boundaries, and root paths. `SourceControlTreeInteractionTests` exercises layout and compact-setting persistence, the live settings sheet, folder expansion, opening a real diff view, staging/unstaging, and a 1,098-file fixture with long horizontal paths and vertical scrolling in both directions. These UI checks use isolated Git fixtures.
