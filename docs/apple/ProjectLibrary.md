# Project organization

The Projects screen supports a flat **All Projects** view and a **Folders** view. One toolbar options button opens a native sheet, with **New Project** first, followed by folder creation and library controls. The sheet switches between the existing **List** cards and a responsive **Grid**, independently of folder grouping. **Recently Opened**, **Name**, and **Custom Order** are available in either layout. Display preferences update in place; actions that open another flow wait for the options sheet to dismiss.

- Touch, hold and drag a project or folder directly in either layout. There is no separate Reorder action or editing mode. The native lift preview includes the rounded card, artwork and status; the space between cards stays transparent. A completed move saves once and selects Custom Order. Cancelled drags do not change organization. Reordering inside a folder only changes those projects' positions.
- **Options → New Folder** creates a group and offers only unassigned projects. Editing a folder separates its current members from available projects. A project belongs to one folder at a time; use **Move to Folder** explicitly to move it between groups. A stale membership picker cannot take a project that another client has assigned elsewhere. Ungrouped projects remain directly visible in Folders view.
- Open a folder to see its projects. Its options sheet can choose projects, rename the folder, or delete the group. A project's context menu can move it to another folder or remove it from its current group.
- New projects created from inside a library folder join that folder, including asynchronous clones that finish after the app closes. Dismissing creation keeps the current folder open, including creation from its options sheet or after optional agent setup. Unscoped creation still opens the new project.
- Empty folders use the same agent artwork and centered layout as the Projects home. They offer existing projects and direct creation; when every project is already organized, **Create a project** becomes the primary action. The empty **Choose Projects** sheet also offers creation, retains its target folder, and dismisses before the creation sheet opens. Project selection uses the same artwork size and text alignment as the library cards.
- Folder cards retain a separate order. List cards, grid tiles, and folder pickers share a preview of up to four cached **custom** project images. Projects without a custom image leave the remaining slots empty. A folder with no custom images uses one filled folder glyph. The preview uses memory already loaded for project cards, without starting file or network reads.

Folder names, membership and custom order are saved in each workspace’s Mindwire registry. The app caches them together with a durable outgoing edit queue in one versioned UserDefaults record, shared across its windows. Layout, view and sort preferences remain local; older saved libraries default to List. Organization works immediately while a computer is offline and syncs on edits or the existing workspace refresh; it adds no idle polling. Drag previews and hovering do not write preferences or queue daemon edits. These edits do not move files, run Git, or copy chat history. An older service keeps organization local until it is upgraded. **Options → Folder Sync** shows pending changes, saved state and retryable errors.

Logical project sync IDs keep membership and order when switching between workspace copies. Registry refreshes merge changed fields while preserving pending local edits; introducing a sync ID migrates the previous project key. An unavailable workspace does not delete its organization. Revisions prevent one phone from overwriting unrelated edits from another. Remote folder deletion removes dependent stale edits, and rejected edits cannot block the queue. The initial local-only migration runs only against an untouched daemon library. Folder deletion preserves project metadata, files, conversations, and ordering.

The UI uses the existing project cards, icons, context menus, native alerts, and native sheet controls. Folders and projects use the same value-based `AppRoute` navigation path. A project opens once, and Back returns to its folder rather than revealing another copy of the project. On iPad a folder opens within the project sidebar, while selecting a project keeps using the existing detail column. Both stacks use the shared route resolver; sidebar selection is inherited by destinations as well as the root list.

Grouped folders use the existing card drag handler in a lazy scroll view for both layouts, including ungrouped projects shown beneath them. This avoids `List` consuming a folder drop after its context menu closes. Flat project lists and the projects inside a folder retain native list reordering. All layouts preserve the same rounded cards and save one change only after a completed move.

`ProjectLibraryTests` covers persistence, stable order after opening a project, single-folder membership and stale picker protection, scoped reordering, naming, workspace-copy migration, canonical clone completion, and preserving data when a folder is deleted. `ProjectLibraryInteractionTests` exercises folder creation, membership filtering, native inline list reordering, grid dragging, and layout/order persistence on iPhone and iPad.

`ProjectLibrarySyncTests` covers offline replay, conflicting clients, deleted folders, older service upgrades, restored databases, single-writer ordering and forgetting/readding a workspace while an old request is still pending. The TS SDK also runs against a real daemon and SQLite registry across restart, with two independent clients. Daemon registry tests check transactional rollback and scoped reordering without moving files or changing conversations.

The native interaction suite targets iOS 26.5 simulators for iPhone 17 Pro Max and iPad Pro 13-inch (M5), with light and dark appearances. It checks creating and selecting folder members, excluding projects assigned elsewhere, switching layouts, restoring folders after relaunch, renaming, moving a project out, deleting a folder while retaining its projects, and dragging into a custom order that survives relaunch. The iPad check also opens a project from a folder without replacing the sidebar.
